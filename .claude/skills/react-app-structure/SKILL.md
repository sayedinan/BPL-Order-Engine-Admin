# React app structure (v0.3)

The frontend is Vite 8 + React 19 + TypeScript 6 + React Router +
Tailwind CSS. The v0.2 single-`AppShell` co-render is gone; each
page is a route.

## The hierarchy

`main.tsx` mounts `App`. `App` is the React Router root. Each route
maps to a page in `pages/`. Pages compose hooks and components.
Components are presentational; they take props and render. No
business logic in a component.

```
main.tsx
  └─ <App />
      └─ <AuthProvider>                    ← AuthContext
          └─ <BrowserRouter>
              └─ <Routes>
                  ├─ /login       → <Login />
                  ├─ /dashboard   → <Dashboard />          (in AppShell)
                  ├─ /logs        → <Logs />               (in AppShell)
                  ├─ /admin       → lazy(() => import('./pages/Admin'))    (in AppShell, SYS_ADMIN/ADMIN only)
                  ├─ /change-password → <ChangePassword />  (in AppShell)
                  ├─ /404         → <NotFound />
                  └─ /403         → <Forbidden />
```

The `AppShell` wraps the authenticated routes; `Login` and the
404/403 pages render without it. The `AppShell` reads `useAuth()` to
get the current user and renders the top bar.

## The role-gated lazy import (🔒)

The Admin Panel is **not in the bundle for `USER` role**. The
mechanism is a lazy import + role check at the route level:

```typescript
const Admin = React.lazy(() => import('./pages/Admin'));

function AdminRoute() {
    const { user } = useAuth();
    if (user?.role === 'USER') {
        return <Navigate to="/403" replace />;
    }
    return (
        <React.Suspense fallback={<div>Loading…</div>}>
            <Admin />
        </React.Suspense>
    );
}
```

A USER's bundle (verified by `npm run build && grep` on the output)
does not include the `Admin` chunk. A USER who manually navigates to
`/admin` is redirected to `/403` by the component, not by the server
(the server would also 403, but the client redirect prevents the
chunk from being fetched at all).

The "hide the link" check is a UX nicety on top of this. The lazy
import + role check is the security boundary.

## Tailwind + Shadcn-style components

Tailwind directives in `src/styles/index.css`:

```css
@tailwind base;
@tailwind components;
@tailwind utilities;
```

Components are Tailwind classes inline. No CSS modules, no
styled-components. The "Shadcn-style" is achieved by:

- A small set of primitive components (`Button`, `Input`, `Select`,
  `Modal`, `Tabs`) in `components/`. These are not generated by
  `npx shadcn-ui add`; they're hand-written but follow the same
  conventions (Radix-style headless primitives + Tailwind
  composition).
- The primitives are in `src/components/ui/`, separate from
  feature-specific components like `EngineCard`.

```typescript
// components/ui/Button.tsx
export function Button({ variant = 'primary', ...props }: ButtonProps) {
    const base = 'inline-flex items-center justify-center rounded-md px-4 py-2 text-sm font-medium transition';
    const variants = {
        primary: 'bg-blue-600 text-white hover:bg-blue-700',
        secondary: 'bg-gray-200 text-gray-900 hover:bg-gray-300',
        danger: 'bg-red-600 text-white hover:bg-red-700',
    };
    return <button className={`${base} ${variants[variant]}`} {...props} />;
}
```

## Type conventions

- `interface` for component props, not `type`. Both work, but the
  codebase uses `interface` for consistency.
- `record` types for API DTOs that match the server's DTOs (server
  uses Java records; client mirrors them as TypeScript interfaces
  with the same field names).
- No `any`. Use `unknown` and narrow.
- `import type` for type-only imports.

```typescript
import { useEffect, useState } from 'react';
import type { EngineResponse } from '../api/types';

export function EngineCard({ engine }: { engine: EngineResponse }) {
    // ...
}
```

## Anti-patterns

- **Don't use Redux, Zustand, or any state library.** `AuthContext`
  and `EngineContext` (if needed) are enough for v0.3.
- **Don't use `axios`.** The native `fetch` wrapper is enough.
- **Don't use `react-query` or SWR.** The data is small, the routes
  are few, and `useEffect` + state is enough for v0.3.
- **Don't put business logic in a component.** Logic lives in the
  hook, the page, or the API client. Components are presentational.
- **Don't fetch data in a `useEffect` that runs on every render.** Use
  the empty-dependency form, or a hook.
- **Don't store the JWT in a non-`httpOnly` cookie without
  `SameSite=Strict`.** A plain cookie gets sent on cross-site
  requests; the JWT in it would leak.
- **Don't import the Admin page eagerly from `App.tsx`.** The lazy
  import is the bundle security boundary.
- **Don't put the engine password in any React state, prop, or
  default value.** The server doesn't return it; the form receives
  it only on the POST/PATCH request body.
- **Don't render unescaped user-supplied strings in JSX.** React
  escapes by default, but `dangerouslySetInnerHTML` is forbidden.
